# AWS
### 클라우드 컴퓨팅
- IT 리소스를 인터넷을 통해 **온디맨드**로 제공하고 사용한 만큼만 비용을 지불하는 것
- 장점
  - 초기 구축비용 절약 가능
  - 용량추정 불필요
- 유형
  - 클라우드 컴퓨팅 모델<br>
![aws_basic_application_structure](/dev-ops/img/aws_basic_application_structure.png)
    1. IaaS(Infrastructure as a Service)
     - 네트워크, 스토리지, 컴퓨팅만 제공
     - OS나 어플리케이션은 직접 설치하는 방식
     - aws에서는 ec2가 IaaS 유형
    2. SaaS(Software as a Service)
     - 모든걸 제공하는 모델
     - 서비스 자체를 제공하기때문에 다른 세팅없이 서비스만 사용할 수 있음
     - gmail이나 슬랙, 구글독스 같은 서비스들이 SaaS 유형
    3. PaaS(Platform as a Service)
     - 네트워크, 스토리지, 컴퓨팅, OS 그리고 추가로 어플리케이션을 실행하기 위한 런타임까지 제공
     - 바로 코드만 올려서 돌릴 수 있도록 구성할 수 있음
     - firebase나 google app engine이 PaaS 유형
  - 클라우드 컴퓨팅 배포 모델
    1. 공개형(클라우드)
     - 모든게 클라우드에서 실행되는 형태로, 낮은 비용과 높은 확장성이 있음 
     - 대표적으로 aws
    2. 폐쇄형
     - 직접 환경을 구축하는것으로 직접 모든걸 커스터마이징 할 수 있다는 장점
     - 초기비용과 유지보수 비용이 많이 든다는 단점
    3. 혼합형(하이브리드)
     - 폐쇄형과 공개형의 혼합
     - 폐쇄형->공개형으로 전환하는 기간에 주로 사용하거나, 폐쇄형의 백업으로 사용

### EC2
- Elastic Compute Cloud의 약자로, 안전하고 크기 조정이 가능한 컴퓨팅 파워를 클라우드에서 제공하는 웹 서비스
- 특징
  - 초 단위 온디맨드 가격 모델
  - 빠른 구축 속도와 확장성
  - 다양한 구성방법 지원
    - 다양한 용도에 최적화 된 서버 구성 가능
  - 거의 모든 aws 서비스는 직 간접적으로 ec2와 연결
- 기본 개념
  - 인스턴스
    - EC2에서 생성한 가상 서버 1대
  - AMI (Amazon Machine Image)
    - OS, 설정, 소프트웨어가 담긴 서버 템플릿
  - 인스턴스 유형(Instance Type)
    - CPU, RAM 스펙
  - 키 페어(Key Pair)
    - 인스턴스에 SSH 접속할 때 사용하는 비밀번호 대신의 키
  - 보안 그룹(Security Group)
    - 방화벽 역할, 포트/접속 허용 범위 설정

### IAM
- Identity and Access Management(IAM)의 약자로, AWS의 보안 및 관리를 담당하는 글로벌 서비스
- AWS사용자 및 그룹을 만들고 관리하며 AWS 리소스에 대한 액세스를 허용 및 거부할 수 있음
- 구성요소<br>
![aws_basic_iam](/dev-ops/img/aws_basic_iam.png)
  - 사용자
    - 실제 aws를 사용하는 사람 혹은 어플리케이션
    - 루트 사용자, IAM사용자 등
  - 그룹
    - 사용자의 집합
    - 그룹에 속한 사용자는 그룹에 부여된 권한을 행사
  - 정책
    - 사용자와 그룹, 역할이 무엇을 할 수 있는지에 관한 문서
    - json 형식으로 정의
  - 역할
    - aws 리소스에 부여하여 aws 리소스가 무엇을 할 수 있는지를 정의하거나, 다른 사용자가 역할을 부여 받아 사용
